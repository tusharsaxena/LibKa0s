## What changed at this version (Skill Master's round 9, rows L1 to L4)

Both files move: `WaypointArrow.lua` 1 -> **2** and `WaypointArrowSettings.lua` 1 -> **2**, for the
owner's round-9 feedback on Skill Master's arrow (Skill Master
`docs/superpowers/plans/2026-11-14-feedback-round9.md`): text formatting, positioning, a larger
arrow, and a right-click menu in place of right-click to clear. Every member, descriptor field,
setting and row of 1.1 is kept; the changes a 1.1 host sees without changing anything are listed
under *Moving to version 2.2* in [the 1.1 document](./version-1.1-docs.md).

### The size (L1)

- **`ART` is `60`** (it was `48`): the art at scale 1 draws 1.25x larger, the owner's new 1.0. A
  host's stored scale keeps its number and draws 1.25x larger than it did.
- Everything is measured in **units** of the art's 48-unit design box (`UNITS`), drawn at
  `ART / UNITS` (1.25) px a unit: the art, Raised's shadow canvas and offset, the ground cell
  (62.5 x 42.97 px at scale 1), the text's gap (`TEXT_GAP`, 2 units) and the frame around the art
  (`HIT_PAD`, 8 units on every side). The TGAs are unchanged: 128 and 512 px, sampled down.
- **The frame is centered on the art.** At 1.1 the art box sat at the top of a frame that held the
  text under it, so the frame's point was the middle of art and text. At 2.2 the frame is the art
  box with `HIT_PAD` round it, so its point is the art's center, and moving the text never moves
  the arrow. The hit rect grows toward the text (`SetHitRectInsets`): by the string's measured size,
  else `TEXT_ROOM` (22 units, the gap included) under or over the box, so the text still drags and
  clicks with the arrow. With the same `DEFAULT_POINT` the arrow sits a few pixels lower than 1.1
  drew it (its center at y = 200, where 1.1's was 11 px higher).

### The text (L2)

- **Ten settings** join `DEFAULTS` and `SETTINGS`. The canonical Font block's six leaves
  (options-ui-§16): `font` (an LSM name, `"Ka0s Prototype"`, `FONT_DEFAULT`), `fontSize` (`6` ..
  `32`, `12`), `fontColor` (`{ 1, 1, 1, 1 }`, either color shape, its alpha applied),
  `useClassColorFont` (`false`: the player's class color through Core's `ClassColor`), `fontFlags`
  (one of `FONT_FLAGS`, `"@skin"`: From skin), `fontShadow` (`true`); its companion `fontFromSkin`
  ("Use the skin's font", `true`); and the block's extras: `textPosition` (one of
  `TEXT_POSITIONS`: `BELOW`, the default, `ABOVE`, `LEFT`, `RIGHT`, `HIDDEN`), `showLabel`
  (`false`: a second line with the target's label under the distance) and `distanceUnits` (one of
  `DISTANCE_UNITS`: `"yards"`, the default, or `"compact"`).
- **The font.** With a skin owner (`d.skin`) whose facade has `HudFont`, the text goes through it:
  no face while "Use the skin's font" is on (the skin's HUD face), the size through `HudFontSize`
  (scaled to the skin's HUD size while it follows the skin), the flags as stored ("@skin" resolved
  by the skin's Font outline), the shadow as stored (`shadowFromSkin = false`: Font shadow is the
  player's). Without one, on the string: the font's face (LSM, else LibKa0s-Media's bundled file,
  else `STANDARD_TEXT_FONT`) or the client's standard face while "Use the skin's font" is on, the
  flags with "@skin" read as `"OUTLINE"`, and a 1, -1 black shadow while Font shadow is on. The
  color is set after it: the class color while Use class color is on, else the swatch.
- **No skin role.** 1.1 painted the text with the facade's `Text("body")` and `Text("muted")`. 2.2
  never calls `Text` on it: the skin replays a `Text` call on every switch and would overwrite the
  player's face and size. The label alone (no distance) is dimmed to alpha 0.6 with or without a
  skin. `HudFont` is not recorded by the skin, so a host calls `Apply()` after a skin change (as
  1.1 already asked) to repaint the face.
- **The default follows the skin as 1.1's did** in face (the skin's HUD face) and outline (From
  skin); its color is the white swatch, where 1.1's was the skin's `text.body`.
- **The distance.** `FormatDistance(yards, units, strings)`: `"yards"` is `STRINGS.DISTANCE` of the
  rounded yards (`"%d yd"`); `"compact"` is the same under `COMPACT_FROM` (1000) and
  `STRINGS.DISTANCE_COMPACT` of the thousands from there (`"%.1fk yd"`: 4210 reads `4.2k yd`).
  **`d.format(yards, units)` is asked first**, now with the units as its second argument; a string
  answer wins, anything else falls back to `FormatDistance` in the configured units with
  `d.strings`. A 1.1 host's `format(yards)` keeps working and ignores the units.
- **Words.** The library carries no locale. `d.strings` (new) overrides `STRINGS` by key, read
  with rawget: `DISTANCE`, `DISTANCE_COMPACT`, `SAMPLE` and the menu's words.
- **The rows** (`WaypointArrowSettings.lua`): the Text block, below.

### The position (L3)

- **Three settings**: `x` and `y` (offsets from the parent's CENTER **in the parent's units**,
  UIParent's for the default parent, `POSITION_MIN` .. `POSITION_MAX`, -2000 .. 2000, defaults `0`
  and `200`, `DEFAULT_POINT`'s) and `lock` (`false`).
- **The units do not move with the Arrow scale.** SetPoint reads offsets in the frame's own units,
  which `scale` scales, so the frame is anchored at `x / scale`, `y / scale`: changing the scale
  grows the arrow where it is, a slider value is the same spot on screen at every scale, and Reset
  position lands on the same spot at every scale. Every point the arrow holds (`d.point`,
  `SetPosition`, `DEFAULT_POINT`, what `onMoved` hears) is in the parent's units the same way; at
  scale 1 they read as 1.1's.
- **Where the frame sits.** Once `x` or `y` is configured, the frame's CENTER sits at those offsets
  from the parent's CENTER; until then the saved point (`d.point`, `SetPosition`) as at 1.1, else
  `DEFAULT_POINT`. `SetPosition(point)` sets configured `x` and `y` aside until they are configured
  again. `GetPosition()` answers the point in use.
- **A drag's end** re-anchors the frame CENTER on the parent's CENTER, in whole units of the
  parent (`(fx * fs - px * ps) / ps`, each center taken to screen units by its effective scale),
  held to `POSITION_MIN` .. `POSITION_MAX` so a drag never stores a value the setting refuses, and **writes
  `x` and `y` through the host**: `d.set(path, value)` at `d.paths.x` and `d.paths.y`, the host's
  architecture-§5 helper, so its sliders follow the drag. `onMoved(point)` still hears the point.
  Where the client answers no centers, the frame's own first point is kept as 1.1 kept it (its
  offsets times the scale, into the parent's units), and no offsets are written.
- **`lock`** refuses a drag while on; `d.canDrag()` still applies as well. `SetLocked(on)` writes it
  through the host; `IsLocked()` reads it.
- **`ResetPosition()`** writes `DEFAULTS.x` and `DEFAULTS.y` through the host, moves the frame and
  calls `onMoved(nil)`.
- **New descriptor fields**: `paths` (the same table as `SettingsRows`' `opts.paths`) and
  `set(path, value)`. Without them the arrow alone holds what a drag, the lock or a reset writes.
- **The rows**: the Position block, below.

### The menu (L4)

- **A right-click opens a menu** (`LibKa0s-Widgets-1.0`'s `W.ContextMenu`, at the pointer, in the
  host's skin `d.skin`) in place of `d.onClick(frame, "RightButton")`. The stock items, in
  `MENU_ITEMS` order, each with an `id`:
  - `clear`, **Clear waypoint**: `d.onClear(target)` when the host has one (it owns the waypoint),
    else `Clear()`. It acts only on the target the menu opened over: if that target arrived or was
    replaced while the menu was open, the click does nothing. **Under the sample** it ends the
    sample only, through `d.onSampleClear()` when the host has one (the host ends its test mode),
    else `HideSample()`; the real target waiting under the sample is never cleared, and `onClear`
    is not called.
  - `share`, **Share in chat**: opens the chat box with `ShareText(target)`, `"/way <zone> 45.2,
    63.1 <label>"`, and **never sends**. The zone is `C_Map.GetMapInfo(mapID).name`, the
    coordinates are percent to one decimal, and the zone or the label is left out when there is
    none. The box is opened with `SHARE_LEAD` (one space) before the line: when a chat box sends,
    the client runs any text whose first character is `/` as a slash command on the player's own
    client (a waypoint addon's `/way`, or "unknown command") and sends nothing, so the space is
    what lets Enter post the line to the box's channel as a message. The box opens through
    `ChatFrameUtil.OpenChat` (12.0 and the clients built on it), else the older
    `ChatFrame_OpenChat` global, whichever the client has. Disabled for a target with no map point
    (a world or provider target, the sample). **The line's shape is the owner's ruling of
    2026-11-14**: the zone and the label stay, so a reader in another zone can use it. The zone name
    is localized and not unique across maps (the Dalarans); TomTom's `#<mapID>` form, the
    unambiguous alternative, was not taken.
  - `map`, **Show on map**: the world map at the target's `mapID`, through `C_Map.OpenWorldMap`,
    else the `OpenWorldMap` global. Disabled with no map point, and disabled and refused in combat
    (`InCombatLockdown`), since the map is a UI panel and the frame otherwise calls nothing that
    could taint.
  - `lock`, **Lock the arrow** / **Unlock the arrow**: `SetLocked(not locked)`, through the host.
  - `reset`, **Reset position**: `ResetPosition()`, through the host.
- **The host's items**: `d.menuItems(items, target, arrow)` is handed the stock list; an answer
  that is a table replaces it (append, insert, reorder, drop), and a host that edits the list in
  place may answer nothing. A row is a `W.ContextMenu` row (`label`, `onClick`, `disabled`,
  `tooltip`, `divider`, `title`, ...).
- **`d.menu = false`**, or a payload without the Widgets major, keeps 1.1's right-click:
  `d.onClick(frame, "RightButton")`. Every other button reaches `d.onClick` as before.
- `MenuItems()` answers the rows as they would open now; `OpenMenu()` opens them as a right-click
  does (false with no frame, no Widgets major or `d.menu = false`).
- **The menu follows the arrow.** The shared menu is a UIParent-parented singleton that only an
  outside press closes, so the arrow closes it (`W.CloseMenu`) when it comes down (arrival,
  `Clear`, `Suspend`) and when the sample starts or ends, while the open menu is still this
  frame's; another owner's menu is left.

## What this major is

A small movable frame that points the way to a target and shows the distance beside it: Skill
Master's own waypoint arrow (owner feedback rounds 6 and 7), moved into the library on the owner's
decisions of 2026-11-14 (Skill Master `docs/superpowers/plans/2026-11-14-feedback-round8.md`, row
L1), and grown in its round 9. It rotates the art toward the target, fades its color from a far
color to a near color by distance, scales, drags (writing its offsets back to the host), locks,
shows its distance in the player's font on any side, opens a right-click menu, and has a sample
for test mode. Five looks ship: **Flat**, **Ridge**, **Raised** (the default), **Faceted** and
**On the ground**, the top artboard of the owner's mockup of 2026-11-14.

It owns no SavedVariables: the host keeps the arrow's settings at its own paths (the settings rows
below), hands them over with `Configure` or `ConfigureFrom`, and stores what the arrow writes (a
drag, the lock, a reset) through its own `set`. It is never secure and calls nothing protected,
so it stays shown and movable in combat. Skill Master is its one consumer; the one-consumer
promotion is a row in the repo's register (`CLAUDE.md`, *Documented deviations*).

| `Get(key)` | One setting as the arrow reads it | **1.1** |

### Measuring

Each measure (on show, then every `THROTTLE` seconds from an OnUpdate armed only while the frame
shows, and disarmed by `Clear`, arrival and `Suspend`) reads the player's world position and facing
and the target's world point. World coordinates: x points north, y points west.
`GetPlayerFacing()` is radians counter-clockwise from north. The rotation is the bearing less the
facing, and `Texture:SetRotation` turns counter-clockwise for a positive angle, so the art, drawn
pointing up, turns toward the target.

- **No facing** (nil, or a secret value, as in instances): the art hides and the distance stays.
- **No distance** (another instance or continent, a secret or unknown position): the label shows
  alone, dimmed to alpha 0.6.
- **Arrival**: within `arrive` yards the target is cleared, the arrow hides and `onArrive(spec)`
  runs.

### The text

The distance (and, while `showLabel` is on and the target has one, its label on a second line)
sits on the `textPosition` side of the art box, `TEXT_GAP` units from it: `BELOW` (the text's TOP
on the box's BOTTOM, centered), `ABOVE` (BOTTOM on TOP, centered), `LEFT` (RIGHT on LEFT,
right-justified), `RIGHT` (LEFT on RIGHT, left-justified); `HIDDEN` hides it, and the art still
points. Its font and color are *The text (L2)*'s.

### The looks

Every look is a **body** tinted with the color and an **overlay** drawn over it untinted, so any
color works: a texture tinted with `SetVertexColor` is multiplied by the tint and can never draw
lighter than it, so the highlights (and the outline, `#1a1410`) live in the overlay.

| Style | Body | Overlay | Turns by |
|---|---|---|---|
| `flat` | `arrow-fill` | `flat-overlay` (the outline) | `SetRotation` |
| `ridge` | `arrow-fill` | `ridge-overlay` (lit left half, shaded right half) | `SetRotation` |
| `raised` | `arrow-fill` | `raised-overlay` (tip-to-tail light, a rim on the leading edges) and `raised-shadow` under it, anchored `SHADOW_OFFSET` down and right so the light stays put while the arrow turns | `SetRotation` |
| `faceted` | `arrow-fill` | `faceted-overlay` (four facets meeting at a peak) | `SetRotation` |
| `ground` | `ground-body` | `ground-overlay` | `SetTexCoord`: one of 72 frames of the angle sheet, the nearest 5 degrees (`GroundFrame`) |

The ground cell is 50 x 34.375 units (62.5 x 42.97 px at scale 1), centered 5.1875 units under the
art box's center. The color is `Mix(far, near, Fade(yards, near, far))`, where far and near are the
skin's `SKIN_FAR` and `SKIN_NEAR` while `useSkinColors` is on and the instance's `skin` answers
them, else the configured `farColor` and `nearColor`.

## The settings rows (`WaypointArrowSettings.lua`)

`SettingsRows(opts)` answers ordinary **path** schema rows for the host's own schema, and (2.2) a
second answer: a table of `afterSubgroup` hooks keyed by subgroup, for `O.RenderRows` or
`O.RenderTabbedSchema`'s `opts.afterSubgroup` (empty when there are none). Every row carries
`path`, `key` (the arrow setting it holds), `type`, `default` (from `DEFAULTS`, a color through
`encodeColor`), `label`, a tooltip (`desc` on 1.1's five, `tooltip` on 2.2's, the field the Options
widgets read either way), `page`, `group`, `subgroup` and `onChange(value)`. In order:

1. **The look** (1.1), on `opts.subgroup`: Style (`string`, `values` = `StyleValues(L)`), Use the
   skin's colors (`bool`), Far color and Near color (`color`, `hasAlpha = false`, each `disabledIf`
   the Use the skin's colors path), Scale (`number`, `SCALE_MIN` .. `SCALE_MAX`, step `SCALE_STEP`,
   `commitOn = "change"`).
2. **The Text block** (2.2), on `opts.textSubgroup` (else `opts.subgroup`): options-ui-§16's Font
   block, Font (`string`, `dialogControl = "Ka0sMedia_Font"`, `startsLine`), Font size (`number`,
   6 .. 32, step 1), Font color (`color` with alpha, `startsLine`), Use class color (`bool`; the
   pair stamped `classColorSource = "player"` and never dimmed, options-ui-§17), Font flags (From
   skin, None, Outline, Thick outline, Monochrome, Monochrome outline), Font shadow (`bool`), then
   its companion **Use the skin's font** (`bool`, `startsLine`, at the font path plus "FromSkin";
   the host names no path for it, and the Font row is disabled while it is on). Then the block's
   extras: Text position (`string`, `TextPositionValues(L)`, `startsLine`), Show the target's name
   (`bool`, `showLabel`), Distance units (`string`, `DistanceUnitsValues(L)`).
   **Given `opts.options`** (the host's `LibKa0s-Options-1.0` instance), the six Font rows and the
   companion are `O.FontGroup{ fromSkin = true, flagsFromSkin = true }`'s own, with the arrow's
   paths as its `keys` and the arrow's defaults: the composer's shape, words, media picker values
   and skin-governed picker (`skinValue`). Without one the rows are built here with the same
   leaves, order, types, defaults and words (compose minor 19's), the Font row's values from
   LibSharedMedia's `HashTable("font")`.
3. **The Position block** (2.2), on `opts.positionSubgroup`, else its own "Position" subgroup (the
   `POSITION` word, PositionBlock's canonical heading; never `opts.subgroup`, so a host that passes
   only `opts.subgroup` still gets the block under its heading): X offset and Y offset (`number`, -2000 .. 2000, step 1, defaults 0 and 200, X
   `startsLine`), then **Lock the arrow** (`bool`, `startsLine`). **Given `opts.options`** the two
   offsets are `O.PositionBlock`'s with the Lock row as its extra, and its **Reset position** button
   comes back as the hook keyed by the block's subgroup; it calls `opts.arrow:ResetPosition()` (when
   the rows are an instance's) and then `opts.onResetPosition()`, and with neither there is no
   button. **Reset position needs `opts.options`**: without an Options instance the block is the X,
   Y and Lock rows alone and there is no button, so such a host draws its own and calls the
   instance's `ResetPosition()`; the menu's Reset position remains either way.

| `opts` field | Meaning | Since |
|---|---|---|
| `paths` | The host's path for each setting: `style`, `useSkinColors`, `farColor`, `nearColor`, `scale`; from 2.2 `font`, `fontSize`, `fontColor`, `useClassColorFont`, `fontFlags`, `fontShadow`, `textPosition`, `showLabel`, `distanceUnits`, `x`, `y`, `lock`. | `page`, `group`, `subgroup` | Copied onto every row (the subgroup as above) | **1.1** |

## Adopting it

```lua
local Arrow = LibStub("LibKa0s-WaypointArrow-1.0", true)
local P = "waypoints."
local PATHS = {
  style = P .. "arrowStyle", useSkinColors = P .. "arrowSkinColors", farColor = P .. "arrowFar",
  nearColor = P .. "arrowNear", scale = P .. "arrowScale",
  font = P .. "arrowFont", fontSize = P .. "arrowFontSize", fontColor = P .. "arrowFontColor",
  useClassColorFont = P .. "arrowFontClass", fontFlags = P .. "arrowFontFlags",
  fontShadow = P .. "arrowFontShadow", textPosition = P .. "arrowTextPosition",
  showLabel = P .. "arrowShowLabel", distanceUnits = P .. "arrowUnits",
  x = P .. "arrowX", y = P .. "arrowY", lock = P .. "arrowLock",
}   -- "Use the skin's font" is stored at P .. "arrowFontFromSkin"

local arrow = Arrow:New({
  addon = "MyAddon", name = "MyAddonWaypointArrow", skin = "MyAddon",
  paths = PATHS, set = NS.SetByPath,                -- a drag, the lock and a reset write here
  canDrag = function() return not NS.Get("locked") end,
  onClear = function() NS.ClearWaypoint() end,       -- the menu's Clear waypoint
  menuItems = function(items)
    items[#items + 1] = { label = "Open settings", onClick = NS.OpenSettings }
    return items
  end,
  strings = { DISTANCE = L["%d yd"], DISTANCE_COMPACT = L["%.1fk yd"], MENU_CLEAR = L["Clear waypoint"] },
  onArrive = function(spec) print("You have arrived: " .. spec.label) end,
})
arrow:ConfigureFrom(NS.Get, PATHS)              -- at load, and after a profile switch or reset

local rows, hooks = arrow:SettingsRows({ paths = PATHS, options = O, page = "waypoints",
  group = "Waypoints", subgroup = "Waypoint arrow", L = L,
  encodeColor = function(r, g, b, a) return { r, g, b, a } end })
RegisterSchemaRows(rows)
-- and when drawing the page: O.RenderRows(ctx, rows, { afterSubgroup = hooks })

arrow:SetTarget({ mapID = 1429, x = 0.42, y = 0.65, label = "Trainer" })   -- show
arrow:Clear()                                                             -- hide
```

The host's profile defaults hold the values (from `Arrow.DEFAULTS`) at `PATHS`, the companion at
the font path plus "FromSkin". A skin change reaches a shown arrow's colors on its next measure;
`arrow:Apply()` repaints the font and the rest at once.

## What a consumer owes

- The art ships whole with the payload, under `media/waypoint/`; nothing is declared.
- A host that stubs this major for a degraded load stubs `New` answering an instance whose methods
  are no-ops (from 2.2 also `SetLocked`, `IsLocked`, `MenuItems`, `OpenMenu`), and `SettingsRows`
  answering `{}, {}`; a stub checked for parity against the lib-level manifest gains 2.2's members
  (`members-2.2.json`).
- From 1.1 to 2.2: see *Moving to version 2.2* in the 1.1 document.
