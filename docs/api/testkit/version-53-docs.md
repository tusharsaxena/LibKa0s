## What changed

### `test_client_globals.lua`: the missing-globals gate (`WFP-LK-06`, LibKa0s#77)

A kit suite, rule `clients-§6`. It fails on a call, in the addon's tracked `.lua` (`libs/` included,
`tests/` left out), of a global function that a client's API does not have, when the addon does not
declare the name and does not guard it. It reads source, so it needs no run to reach the line:
`SetDesaturation(x, true)` is absent from both clients and a headless run never reached it.

- **Wiring:** one entry in the consumer's suites, `{ name = "test_client_globals", dir = "tests/_kit/" }`.
  The suite inventory goes red until it is there. Optional facts, set before `Kit.run`:
  `Kit.clientGlobals = { root = ".", allow = "tests/client_globals_allow.lua", skip = { "tools/" } }`
  (`skip` is path prefixes of tracked files that never ship).
- **Clients:** `live` always. `forever` only when a root `.toc`'s `## Interface` line carries a 16xxx
  number, so a Retail-only addon owes Forever nothing.
- **What it reports:** `file:line name client`, one per call and client.
- **Findings:** a bare call `Name(`, or `C_Name.Member(` where `C_Name` is a namespace some client
  knows, whose name is missing from that client's set.
- **Heuristics, all lenient:** comments and strings are blanked first; a name the addon declares
  anywhere (`local`, `function`, a parameter, a `for` variable, a global assignment) is its own; a
  name the same file mentions other than as a call is guarded (`if X then`, `X and X(`,
  `local f = X`, `type(X)`, `pcall(X, ...)`), and for a namespace member a bare reference to the
  namespace guards it. Method and field calls are never findings.
- **The allowlist:** `tests/client_globals_allow.lua` returns `{ { name = "X", reason = "why" }, ... }`.
  A row with no reason fails, and so does a row no finding reaches (checked against both clients,
  whatever the TOC asks for). An absent file is an empty list.

### `client_globals.lua`: the scanner

`strip(src)`, `declare(code, into)`, `scan(files, sets)`, `collect(root, skip)` (raises with no
`io.popen`, no git or no source), `sets(dir)`, `clientsFromToc(toc)`, `allowlist(path)` and
`judge(found, allow, clients)`.

### `client_globals_live.lua`, `client_globals_forever.lua`: the name sets

Generated by LibKa0s's `tools/client_globals_data.lua` from Ketho/BlizzardInterfaceResources
(`Resources/GlobalAPI.lua` and `Resources/FrameXML.lua`). Each file records the branch, the commit SHA
and its date. live: `f3b334b33bd19fa6a0250f7922ecfa83db7fe356` (2026-10-22), forever:
`d1ee569878094270c0ad8d8b00de0762158fd578` (2026-10-21). Forever is stored as `added` and `removed`
against live. They sit flat in the kit folder, not under `data/`, because the kit vendors as one
folder of files and its sync gate lists a folder's plain files only.

## What a consumer owes

Re-vendor the kit with the library, add the suite entry above, and either guard each call the gate
names or list it in `tests/client_globals_allow.lua` with the reason. The name sets are a snapshot:
a regeneration is a kit revision.
